# 教程的实践检查

## 同题案例：重试机制

以下是自拟教学设计，具体代码与输出须以目标产品验证。

- 读者起点：能运行脚本，能找到日志；不要求已经理解重试策略。
- 练习成果：在隔离环境运行一个先失败后成功的请求。
- 学习目标：观察一次逻辑操作可能包含多次请求，识别尝试次数与最终结果。
- 路线：运行固定示例，看到失败记录，再看到成功记录；指出两条日志的关联标识。
- 收尾：重复练习，确认结果可复现。延迟策略与重复副作用的深入讨论另行链接。

应提前确认模拟故障不会影响真实服务；示例使用哪种故障、如何重置、预期日志是什么，都不能临时编造。

## 常见失败

| 失败 | 修正 |
| --- | --- |
| “适合零基础”，却默认读者会设置环境变量 | 用可观察能力声明起点；补足当前路径所需知识 |
| 第一步列出五种数据库让学习者选择 | 为这次练习选定一种；说明它是练习选择 |
| 命令执行成功，读者不知道发生了什么 | 提供结果和观察点，而不是只说“成功即可” |
| 把部署成功等同于学会部署 | 区分成果与学习目标，承认尚未覆盖的能力 |

中文表达例：把“本教程将使你获得对于重试的理解”改成“这次练习会让请求先失败，再重试成功。运行后，观察日志中的两次请求记录”。
