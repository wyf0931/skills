# 操作指南的实践检查

## 同题案例：为调用配置重试

以下是自拟设计，不能直接充当某个 SDK 的规格。

目标读者已经会调用该接口，需要配置重试。写作前确认哪些操作允许重试、失败条件、配置入口和如何判断生效。

必要的判断应该显式出现。例如先区分只读请求与可能重复产生副作用的请求，再按接口契约选择重试路径。不能用“配置适当的次数”代替选择依据，也不能擅自假设写请求不支持安全重试。

指南可以是带分支的步骤，也可以是检查清单。实际依赖决定结构；无需从安装语言环境开始。

## 常见失败

| 失败 | 修正 |
| --- | --- |
| 标题只有“重试功能” | 说明具体目标，例如“为查询请求配置重试” |
| “选择适当的选项” | 给出判别条件；信息不足时向作者确认 |
| 先执行，再在结尾说明会中断服务 | 在受影响步骤之前说明后果和所需准备 |
| 步骤结束于“保存” | 给出能判断配置生效的检查，依据实际产品填写 |

中文表达例：把“完成其配置后应用它”改为明确对象和动作的指示；如果产品存在热加载与重启两种方式，先说明区分条件，再给操作。
