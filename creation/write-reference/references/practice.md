# 参考文档的实践检查

## 同题案例：重试配置项

以下为自拟查阅问题，不是某个产品的真实参数。

对于“最大重试次数”，应根据实际资料核实：

- 参数精确名称、类型、合法范围。
- 数值是否包含首次请求。
- 省略、显式设为零、空值分别如何处理。
- 哪些失败会重试，哪些不会。
- 是否受总超时限制，是否可能有重复副作用。

这些问题比单独给出一个成功调用例子更能揭示描述缺口。资料未说明时，向作者列出待确认事项，不填入猜测值。

## 常见失败

| 失败 | 修正 |
| --- | --- |
| 只给函数签名和成功示例 | 补充影响调用决策的行为约束 |
| 把“可选”当成默认值说明 | 分别说明省略时行为和有无默认值 |
| 参考页依赖“之前的教程”才能知道对象怎么获得 | 简述必要调用上下文，链接具体入口 |
| 用近义词润色同一个配置项 | 保持术语稳定，避免制造不同对象的印象 |

中文表达例：将“该配置作用于其后续请求”改成明确主语和作用范围的陈述；必须先确认“后续”指连接、客户端实例还是全局请求。

## 实践来源

- [HN：Examples are the best documentation](https://news.ycombinator.com/item?id=45532090)同时包含依赖示例与需要明确契约的读者观点；这是需求差异，不能变成“所有文档只需示例”。
- [Redis SCAN](https://redis.io/docs/latest/commands/scan/)描述语法、版本、复杂度和迭代保证及限制；借鉴其边界描述，实际规则仍须核对目标版本。
- [Rustdoc 写作指南](https://doc.rust-lang.org/rustdoc/how-to-write-documentation.html)中的 `args()` 示例交代平台差异和 panic 条件。
