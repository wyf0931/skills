# 中文文风蒸馏：统计与 Agent 的职责划分

研究日期：2026-11-03。本文修订此前“去掉运行引擎、改成指令优先”的建议：移走采集和独立模型编排，但保留小型、可复现的统计内核。尚未迁移或实现新 skill，旧 `oma-skills` 目录只读。

开源 skill 的具体代码核对见 [项目记录](style-distillation-projects.md)。本文补充传统文体统计、旧实现的小实验与候选架构。架构和特征选择均为待验证设计，不是已经证明对中文政策、宣传或古文有效的成品。

## 社区发现与使用范围

- [HN：2022 stylometry 项目](https://news.ycombinator.com/item?id=33755016)中的讨论指出词频向量可能混淆话题与文风；这是一条需要用实验检验的风险提示。
- [HN：antirez 复现](https://news.ycombinator.com/item?id=43705632)链接到可读的第一方文章和代码。它研究相似度，不是文章生成。
- 搜索了 X/Twitter 上的 `writing-dna-skill`、`style-distiller`、`stylometry skill` 等组合，未获得可核验的相关原帖。没有把聚合站或转述包装成 X 上的项目验证。

## 有代码的统计方法

### antirez/hnstyle：词频向量，不使用 LLM

[第一方介绍](https://www.antirez.com/news/150)及[源码快照](https://github.com/antirez/hnstyle/tree/cc704c1d993f1704c6cae7fc40cd0d69a408ef9f)。已读 `insert.py`、`gen-freqtab.py`、README 和 BSD-2-Clause 许可。

它预处理词频、计算相对频率和总体统计，再构建标准化向量存入 Redis 做相似检索。作者提醒，扩大词表可能让结果更多反映讨论内容。这说明简单统计有可实现的用途，但相似检索不能证明写作风格迁移成功。我们的规模不需要引入 Redis；也不应把该演示直接称为标准 Burrows' Delta 实现。

### computationalstylistics/stylo：成熟的文体统计工具

[项目](https://github.com/computationalstylistics/stylo)；核对快照 `856f5f469ee808d367e5fcb31b938d30f37863dd` 中的 `R/dist.delta.R`、`R/perform.culling.R` 与 DESCRIPTION。

源码展示两种重要操作：按出现文档的比例筛选特征（culling），以及将频率标准化后计算平均曼哈顿距离（Classic Delta）。[第一方跨语言说明](https://computationalstylistics.github.io/blog/stylo_and_languages/)明确要求考虑中文的字符特征及语料平衡；不主张所有语言使用同一组参数。

可借鉴特征归一化、文档覆盖率、采样和距离分析，不必为小型 skill 引入整个 R 工具链。

### mcjkurz/qhchina：面向中文分析的 Python 路径

[固定源码](https://github.com/mcjkurz/qhchina/blob/dbb78c653219925763a09adb06565b862dc8e427/qhchina/analytics/stylometry.py)，MIT。已读核心特征构造、相对频率、culling、标准化及比较方法，未执行全库。

`fit_transform` 接受预先 token 化的文档，提取 n-gram，按文档覆盖筛选特征，建立相对频率向量，再进行标准化等处理。库还提供距离、聚类和词汇统计。可借鉴其“逐篇特征矩阵”思路；中文分句、引文识别及目标文体的特征定义仍需我们负责。

### 中文功能词研究：有用，但不能宣称天然去除题材干扰

[Bei Yu，Function Words for Chinese Authorship Attribution，2012](https://aclanthology.org/W12-2506/)。研究以中文功能词频率做作者分析，发现体裁与作者信号可能相互干扰，其强弱依数据集而变；论文也说明样本规模等限制。

因此，“之、而、其、于、的、了”等可以成为候选特征，但不能直接用来宣称识别出作者本质，或证明生成文言文质量。本文不把其作者归属实验成绩挪用为我们未来的文风迁移成绩。

## 旧实现的小实验

只读取并以 AST 提取旧文件 `skills/style-maker/vendor/oma-docs-distill/distill_agent/text.py` 的 `extract_candidate_ngrams` 函数，在内存运行，没有导入旧包、写入旧目录或调用模型/API。

人工输入为 `"甲乙。丙丁。" * 6`。函数先用 `"".join(CHINESE.findall(text))` 去掉标点并拼接全文，再寻找重复片段，输出：

```text
甲乙丙丁甲乙丙丁
乙丙丁甲乙丙丁甲
丙丁甲乙丙丁甲乙
丁甲乙丙丁甲乙丙
```

四个候选均不作为连续字符串出现在原始输入中。实验只证明这段实现会制造跨边界候选，不代表已经测量真实政策语料的误差率。

另有静态检查发现：当前 `token_frequencies` 过滤长度小于 2 的 token，可能丢失单字功能词；全库候选先汇总，再让模型审词，缺少逐篇覆盖和对照；它更接近“候选术语发现辅助”，尚不是完整文风画像。

## 需要保留和升级的统计

| 特征组 | 脚本可提供的证据 | 不应直接推断的结论 |
| --- | --- | --- |
| 句段形态 | 中文断句后的字符长度分布、分位数、段长、标题密度、分项形式 | 长句必然庄重、短句必然有力 |
| 标点和功能词 | 分角色计数及每千字符频率，给出分母和样本数 | 某个标点应该被禁止 |
| 连续表达 | 不跨句段的字符 n-gram、实际原文位置、总频次和文档覆盖率 | 高频就是固定搭配或作者偏好 |
| 候选搭配 | 可选的共现强度、左右上下文丰富度，结合最低支持度 | PMI 高就是好词或必须复用的词 |
| 样本内差异 | 逐篇向量、分组差异、异常文档及重复段落比例 | 混杂文章必定属于同一风格 |
| 对照差异 | 与同文体、近主题背景材料的相对差异 | 单一距离等于模仿质量或置信概率 |

统计报告应同时保留逐篇结果与汇总。不能让一篇很长的文章或大量转载材料主导规则。字符统计和分词统计使用各自清楚的单位；现代中文常见停用词对文风可能有用，不默认全删。词汇丰富度需要控制文本长度，不能简单比较不同长度文章的 TTR。

没有匹配的背景材料时，仍可报告样本内部模式，但必须说明无法判断它是“独特偏好”还是“常见文体惯例”。

## 对中文目标文体的适配

下列是设计判断，需要真实语料验证。

**政策材料**：将政策名称、引用条款、机构、人名与可迁移表达分开。比较分项结构、限定语、动词搭配和论证顺序；模板性重复与正式引文单独标记。

**政府宣传文章**：观察段落推进、事例与评价的衔接、标题句式和叙述视角。统计出排比或四字表达后，由 Agent 判断功能与条件，不能套用通用反 AI 禁词表。

**古文创作**：不默认现代汉语分词或英文句法模型适用。先用字符、虚词、句式及章法证据；现代整理者所加标点不能全部归为原作者风格。异体、繁简处理应记录转换，并保留原文。用典与训诂需要可靠文本依据，不能仅靠字频判断。

**现代古文讲解**：另作现代中文文体处理，区分引文与讲解正文，避免把引用文言的高频字误判为讲解者的习惯。

## 候选架构：确定性证据层 + Agent 解释层

```text
已准备的语料
  → 边界保留、去重与分组
  → 本地可重复计算的特征与原文位置
  → 分布、对照及代表样本
  → Agent 解释章法、修辞与适用条件
  → 自包含文风 skill
  → 机械复查 + 留出文章/新主题复核 + 人工评阅
```

首版建议一个 `distill-zh-writing-style` skill，内含小型分析与检查脚本，共用特征定义；不用拆成“词频 skill”“标点 skill”等用户目标不独立的技能。

**脚本负责**计数、比例、抽样、来源位置、重复检测、距离与报告；不得调用 LLM 来伪装这些数值是测量结果。核心分析应能离线完成，输出稳定顺序和明确参数。分词或更复杂的语言分析可作显式可选增强。

**Agent 负责**解释为什么这样组织、哪些证据支持修辞判断、何时适用，以及将结论编译成可读的写作规则。所有规则标明属于测量支持、解释性推断还是用户要求；观测频率不直接变成硬约束。

**生成物负责**实际写作。基本使用应自包含；机械检查器可作为随包增强，不能依赖蒸馏器的绝对路径或整个原始资料库。事实、引语和具体经历不随文风转移。

## 与旧版及前一轮方案比较

| 方面 | 旧 style-maker | 前一轮轻量建议 | 研究后的修订 |
| --- | --- | --- | --- |
| 数值证据 | 词频/n-gram 辅助模型 | 指令和原文证据为主 | 保留独立统计内核，修正边界与分母 |
| 语义解释 | 逐篇模型分析再汇总 | 宿主 Agent | 宿主 Agent，引用测量和原文 |
| 采集 | 内置 fetch 后备 | 移出 | 移出，输入契约明确 |
| 模型编排 | 独立 API、LangGraph | 移出 | 移出，统计脚本不调用模型 |
| 输出 | 固定 9～10 份参考 | 按需小包 | 按需小包，包含必要测量摘要及证据 |
| 验证 | 文件与状态为主 | 任务/反例检查 | 留出验证、对照消融和事实检查 |

这里的“蒸馏”是将语料编译为统计画像与可执行规则，不是训练学生模型，也没有更新模型权重。

## 如何判断统计层是否值得

设计同一语料和任务下的三路比较：只给范文；范文加 Agent 归纳；相同条件下再加入确定性统计证据。它们共用模型及写作素材，保留未参与提炼的文章；近重复稿件必须放在同一划分中。

再加两个交叉条件：同题材不同风格、不同题材同风格。分别检查原意与事实保持、表面特征距离、较长连续片段复用和人工文风评价。不要合成未经校准的“文风还原率”。零方差、空文本、样本不足、文体混杂及标点后加等情况，应明确提示而非输出虚假精度。

当前没有用户真实语料包，尚未运行这组实验，不能预先承诺混合方案一定优于纯提示词。现有证据足以支持把它作为优先验证的技术路线。
