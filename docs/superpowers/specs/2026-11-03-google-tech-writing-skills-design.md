# Google 技术写作课程规则沉淀方案

## 目标

把本地“Google 技术写作”系列中可复用的写作规则，按适用范围沉淀进个人 skills。跨文体规则进入 `creation/write-clearly`；文体专属或产品场景规则留在对应 skill，避免五个文档类型互相覆盖，也避免把英语规则机械套用于中文。

## 方案

1. 扩充 `write-clearly`：纳入读者知识差、术语一致性与定义、歧义代词、强动词、双重否定、短句与拆分、列表和表格选择、图示说明及非颜色线索、自我编辑的分轮检查。明确所有格式选择以内容和媒介为准，不设置句长、段长等僵硬阈值；编辑时保留原意、限制条件和不确定性。
2. 扩充现有文体 skill：依据其实际任务吸收范围和前置条件、目标导向标题、开篇摘要、渐进式披露、导航和大型文档信息组织。教程与操作指南按任务顺序组织；参考文档强调查找；解释强调概念关系。避免新增一份通用文档大纲。
3. 新增 `write-error-messages`：处理面向用户或开发者的错误消息写作。涵盖读者与语气、具体指出问题和无效输入、解释约束、可执行修复建议、例子、术语一致、简洁易读、错误附近呈现、按需链接详细文档。把后端错误模型、日志、错误码与面向用户的文案区分清楚，不将课程建议误当作所有系统的实现要求。
4. 新增 `write-accessible-content`：供文档、网页和配套视觉内容的无障碍审阅使用。涵盖有意义的标题层级、链接文字、适合上下文的替代文本、非颜色线索、对比度、直白语言及避免偏见表达。区分文本建议与需要实际渲染、读屏或对比度工具验证的事项；不虚称验证已完成。
5. 对示例代码和 LLM 辅助写作不新建 skill：在 `write-tutorial` 中加入与可运行、可理解、可复用和副作用相关的示例代码注意事项；在 `write-clearly` 中说明 AI 辅助改写仍需逐项核对事实、条件和术语。只有出现稳定独立的重复需求时再拆分。
6. 更新双语 README、安装命令、NOTICE 与验证记录。说明 Google 来源和 CC BY 4.0；规则是课程内容的精炼和中文适配，不声称 Google 背书。

## 验收

- 新增技能均有标准 frontmatter、边界清楚、自包含，不依赖兄弟 skill 或仓库运行时文档。
- 现有技能的职责没有因重复规则而模糊；双语目录和安装说明一致。
- 对每个新增或实质调整的 skill 做一个真实任务桌面演练和一个边界场景；明确标注未做的宿主运行测试和读者测试。
- 运行仓库要求的结构检查和单元测试；对新 skill 做元数据验证。

## 来源范围

本地系列共 47 篇课程文章，涉及技术写作基础、进阶写作、无障碍和错误消息。导论、总结和练习页用于理解课程范围；规则提取以具体教学单元为依据。原文及代码片段许可不同，skill 仅概括规则，不复制课程示例或图片。Google 课程概览及站点许可在 2026-11-03 核对；课程内容默认 CC BY 4.0，代码示例另依 Apache 2.0，图片和外链媒体可能有单独许可。
